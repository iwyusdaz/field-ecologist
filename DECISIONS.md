# Decisions — Field Ecologist: Sampling the Meadow

Every decision with alternatives and rationale; deviations from the plan included.

| # | Decision | Alternatives considered | Rationale |
|---|---|---|---|
| 1 | Seeded population from a Thomas/Poisson/gradient process (one documented seed, `MEADOW_SEED = 20260535`) | Hand-placed plants; procedural-only with random seed per session | A known truth makes the reveal possible; a fixed seed makes unit tests, the reveal and re-sampling reproducible. Chosen from a scan of consecutive seeds so realized totals sit near the parameter expectations (documented in `design/ecology-model.md`). |
| 2 | Convenience design modeled as "60 % near visible showy clusters + 40 % near the gate" | Free learner placement only; pre-scripted biased set | Free placement IS available (map click or x/z inputs), but the modeled bias reproduces real convenience behaviour even when a learner places "randomly feeling" points; both paths appear in the reveal. Honest description in the design picker. |
| 3 | Wind reduced to ~12 % (not 0) inside the counting view; 0 under reduced motion | Full wind always; hard pause always | 12 % keeps the meadow alive without hurting legibility of the counted plants (counting affordance, like parting the sward); reduced-motion users get a full pause. Documented in `design/realism-matrix.md`. |
| 4 | No bloom in the post pipeline even though the preset table lists `bloom-light` | Bloom on High+ | Nothing in an overcast daylight meadow physically motivates bloom; restrained post (SMAA on Medium+, N8AO on High+ only). The preset array is template heritage; `post.js` reads only `smaa`/`aoEnabled`. |
| 5 | Never thin instances inside the active quadrat (preset density applies outside it) | Thin everywhere for perf | On Low (40 % density) the learner would count a systematically wrong sample — the estimate must match the truth on every preset, or the reveal lies. Perf impact is bounded (one 2 m radius per active quadrat). |
| 6 | Field marks slightly exaggerated in the models (blade widths ~2–3× real; head contrast boosted) | Strict real-world dimensions | At the counting view's pixel scale, real 2–4 mm blades are sub-pixel. Plan §13 explicitly allows exaggeration documented in the realism matrix; the field guide states real dimensions while the in-app note says marks are exaggerated for legibility. |
| 7 | Billboards (imposters) baked at startup from the real geometry, square framing from the bounding box, per-plant yaw | Pre-rendered sprite sheets (build step); SSG imposters; 3D LOD models | No build-time tooling or extra assets; per-plant yaw keeps billboards correct at any angle; one 128 px bake per species at startup costs ~ms. |
| 8 | Content JSONs bundled via Vite JSON imports (not fetched from `public/`) | Copy `content/` into `public/` at build | Fetching from `public/` duplicates the source of truth; JSON imports keep `content/` as the single versioned source and avoid sub-path fetch edge cases. Editing content requires a rebuild (acceptable; CI rebuilds anyway). |
| 9 | Self-hosted decoders via `vite-plugin-decoders.js` (dev middleware + build copy); GLTF/KTX2 loader imports removed from `assets.js` | Vendored `public/decoders/` (trips security scanners); dropping decoders entirely | The build contract wants decoders inside the build; the plugin serves them from the pinned three package with zero vendored files. The loader imports were removed because importing DRACOLoader/KTX2Loader makes Vite emit *duplicate* decoder copies into `dist/assets/` (~1.9 MB) even though this fully procedural project loads no GLB/KTX2 assets. The decoders remain in `dist/decoders/` for future-proofing. |
| 10 | Playwright config at the repo root (testMatch restricted to `*.spec.js`), repo-unique ports (4179/4189), `--host 127.0.0.1` preview | Template's `tests/playwright.config.js` (never auto-discovered from the repo root); port 4173/4180 | `npx playwright test` from the repo root (what package.json and CI do) only discovers a root config; the template location also risked sweeping vitest's `*.test.js` files into Playwright. Unique ports avoid cross-repo clashes on the shared dev machine (a sibling repo's server was observed squatting on 4173 during the build). IPv4 host because `vite preview` otherwise binds `::1` only and the URL health check targets `127.0.0.1`. |
| 11 | Text mode reuses the session/data-sheet/reveal/report modules; the grid is 20×20 with rows = x bands (so the moisture-zone column is geometrically correct) | Rows = z bands; separate text-mode logic | `zoneOf` is a function of x, so only rows-as-x-bands make the zone column honest. Shared modules guarantee parity instead of approximating it. Text-mode points snap to cell centres; snapping is a text-mode-only affordance (documented in the design doc). |
| 12 | Pre-check/ID-quiz answers accepted in any order; no module locking except the reveal (needs submitted data) | Hard linear gating | Teachers can jump to any module for demos; the one lock that matters pedagogically (reveal after commitment) is enforced ("the reveal comes only after the data is submitted"). |
| 13 | The learning record is local-only, xAPI-shaped, exportable, with per-project "Clear my data" | Server backend; xAPI LRS | No infrastructure/privacy surface; standards §7 prescribe local-only. |
| 14 | Sub-path spec's static server resolves directories to `index.html` | Template's server (crashed with EISDIR on the page URL) | The page URL `/play/<slug>/` resolves to a directory; the template server only handled the missing-file case. |
| 15 | Poster captured via Playwright `page.screenshot` (webp/jpeg) of the running scene with the HTML chrome hidden, after programmatically freezing the auto-cinematic | `canvas.toDataURL` after a manual render (produced stale/blank buffers without `preserveDrawingBuffer`) | Screenshot captures exactly what the composited engine loop shows; Chromium encodes both formats natively, so no extra dependencies. |

## Deviations from the plan

- **No `v1.0.0` tag** (plan §8 phase 8): per orchestrator instruction the owner/orchestrator tags releases; package.json is at 1.0.0 and the release workflow is in place, so tagging later fires the same pipeline.
- **`scripts/build-species-models` / `bake-imposters` as offline build steps** (plan §7 tree): species models are built at runtime from `src/systems/species-models.js` and imposters are baked at startup — no offline artifacts to keep in sync. Rationale: models are ~100 lines of primitives each; a build step added nothing.
- **The "reveal vs estimate" table also includes the Bunchgrass cover comparison** and personalized error-source notes (bias highlighted for the convenience design; mis-ID noted when the ID quiz recorded mistakes) — an extension of plan §5.2's reveal to make the error sources concrete for the learner's own run.
- **Systematic design draws a random grid offset once** and the stratified design puts the remainder quadrat in the wet stratum — matching `content/designs.json` copy, which is the learner-facing contract.
